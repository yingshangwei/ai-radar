# 服务端管理员对话

启用 `chat.agent_enabled=true` 后，Chat 的所有接口（包括历史）要求管理令牌；阅读令牌不能执行命令或读取运维对话。保留会话切换、Sol/Astra 模型选择、FIFO、调用计量与未知结果不重放规则。自动总结、翻译、发现任务继续关闭工具；执行模式参与用户对话的请求指纹。

`chat.external_worker=true` 与独立 `ai-radar-chat.service` 配合使用。部署时只运行一个 worker。API 重启不会终止 Chat；worker 意外退出由 systemd 恢复，持久化回执用于恢复已完成答案。不确定是否执行的命令不会自动重复，新消息应先检查实际效果。`timeout_seconds` 可配置到 3600，默认成本档仍为 Sol medium。

## 给服务端助手的操作约定

- 用户对话可处理一般问题、代码、数据分析和服务运维；快照只是起始参考，使用工具核对最新事实。
- 实际项目在 `/opt/ai-radar/current`，配置在 `/etc/ai-radar/config.toml`，数据在 `/var/lib/ai-radar`。进程日志可用 `journalctl -u ai-radar.service`；不要输出完整环境、令牌、授权文件。
- 修复前备份目标文件并记录哈希，检查活跃任务和数据库事务。修改通用代码后先编译/测试，再用 `sudo -n /usr/bin/systemctl restart ai-radar.service` 重启，验证 `/healthz`。失败恢复备份。不要修改其他站点、VPN 或无关服务。
- 修改代码/配置后更新 `source-manifest.json` 对应文件的 SHA256（保留其他条目和历史），保存修改说明和差异。不能伪造检查结果。服务器未配置 Git 推送凭据时，将差异保留并告知本地开发任务同步，不能声称已经推送。
- 文章、译文、审核状态只能由正式服务流程生成。发现内容问题应修复通用逻辑，不直接改数据库内容。保留事实限定条件和证据审计。
- 不要重启自身 `ai-radar-chat`；自身升级由外部部署完成。对未知执行结果先只读核对，不能重复付款、删除或批量改写。

工具不限制聊天主题。系统账户的权限隔离和管理令牌仍然生效。新部署需给该账户 Radar 源码与配置的写权限，并经 `visudo -cf` 校验安装所附的服务控制规则；主 API 保持原有只读文件系统隔离。
