# 持久化中文版本

翻译在服务端采集、导入和日报整理时完成。手机端默认中文，可切换原文；阅读、搜索、刷新、收藏、离线缓存均不触发模型调用。原始 `title` / `text` 完整保留，API 另提供 `title_zh` / `text_zh` 和 `translation.status`。

开发工作的边界是改进服务器流程。发现错译后，应增加可复现的回归、修复翻译或审核逻辑，再由服务器按原文处理；不能直接替换文章或译文、手工批准候选，或为某一篇另写内容修补脚本。历史人工修订仅保留为审计记录，通过正式重审流程恢复为服务器生成和审核的结果。

## 配置

将 `DEEPSEEK_API_KEY` 保存在 `/etc/ai-radar/server.env`（0600），不要放入仓库、移动端或日志。在 `/etc/ai-radar/config.toml` 中启用：

```toml
[translation]
enabled = true
base_url = "https://api.deepseek.com"
api_key_env = "DEEPSEEK_API_KEY"
model = "deepseek-v4-flash"
review_model = "deepseek-v4-pro"
# audit_model 可单独指定；省略时使用 review_model，但仍是独立调用。
review_max_rounds = 2
revision = "zh-v1"
concurrency = 2
max_documents = 100
max_attempts = 3
```

摘要的 `[provider]` 独立配置，仍可使用 Codex CLI、Claude CLI 或模型 API。翻译使用现有 OpenAI SDK 的兼容接口，可通过 endpoint、密钥环境变量、模型和 `request_options` 替换。其他服务不支持 DeepSeek 的 `thinking` 参数时，配置 `request_options = {}`。

`stage_request_options` 可分别配置 `draft`（初稿）、`correction`（修订）、`audit`（独立审计）。没有配置该阶段时使用公共 `request_options`；阶段键存在时，其对象**完整替换**公共对象，不做合并，显式 `{}` 表示不发送额外参数。其他服务的参数仍可透传，供应商自己的嵌套对象（如 `thinking`）可以使用；不要再包一层 `extra_body`。空对象不等于关闭供应商默认推理模式，关闭时须按该供应商的接口显式配置。

公共及阶段 options 均不能覆盖 `messages`、`model`、`response_format`、`tools`、`tool_choice`、`functions`、`function_call`、`stream`、`stream_options`、`max_tokens`、`max_completion_tokens` 或 `extra_body` 等正式流程字段。模型使用上述专用字段；输出预算使用 `max_tokens` 和 `stage_max_tokens`，均为 256–65536 的整数。公共预算默认 12000，阶段未指定时继承公共预算。配置校验报错不回显输入值。

下面的推理配置示例说明如何单独启用修订和审计。初稿继承默认的非推理模式与 12000 token；修订和审计分别完整配置推理参数，并使用 32768 token 预算：

```toml
[translation]
request_options = { thinking = { type = "disabled" } }
max_tokens = 12000
timeout_seconds = 300

[translation.stage_request_options.correction]
thinking = { type = "enabled" }
reasoning_effort = "high"

[translation.stage_request_options.audit]
thinking = { type = "enabled" }
reasoning_effort = "high"

[translation.stage_max_tokens]
correction = 32768
audit = 32768
```

分阶段配置于 `20260908-4d196af` 部署时启用，后续代码升级沿用该配置：`correction`、`audit` 均为 `thinking.type=enabled`、`reasoning_effort=high`、32768 token，单次 SDK 调用整体超时为 300 秒；初稿仍为 disabled、12000 token。当次配置切换只改这七个字段，14 张数据表、七组历史记录、其他配置与既有服务保护检查均通过。

官方 [DeepSeek 思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)说明 V4 支持 `thinking` 和 `reasoning_effort`。OpenAI SDK 将 `thinking` 放入 `extra_body`；本项目的 options 会作为该对象发送，最终位于 HTTP 请求体顶层。当前翻译流程不携带工具，无需回传 `reasoning_content`；只解析最终 `content`，不保存或记录思考内容。推理模式不改变现有 JSON、段落对应、保护标记、机器检查和独立审核门槛。

`timeout_seconds` 默认为 120 秒，限制每次 SDK 调用的整体时长，包含该调用内部重试；格式恢复仍最多一次，两次调用各受时限约束。不能只依靠连接读超时判断总时长，因为供应商可能发送[保活空行](https://api-docs.deepseek.com/quick_start/rate_limit/)。输出预算需为推理和最终 JSON 留出空间；即使使用 [JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)，空响应、截断或非 `stop` 结束仍会拒绝。推理参数和预算不会使已通过缓存失效，也不增加语义修订轮次或结构恢复次数；调整后应先进行有范围的正式验证，不能据此宣称模型保证准确或反复运行未变化的失败流程。

## 缓存与恢复

- 缓存键包含原始标题、正文、目标语言、术语表和 `revision`。互动数字、收藏、来源记录 ID 不参与；同内容跨记录共享译文。更改模型不会使全部缓存失效，明确更改 `revision` 才重新生成。
- 原文变更会排队新译文，接口不会展示旧内容的译文。历史收藏和日报引用也会补齐中文。
- 长文分段处理，不截断正文；已生成草稿、已通过校对的段落分别持久化。失败后只恢复未完成步骤。
- 数据库租约防止不同任务同时翻译同一内容，写入时同时核对持有者和租约有效期。已明确结束的网络故障可有界恢复；租约过期本身不能证明在途调用失败。每轮最多处理配置数量的可继续文档。
- X 等来源的标题是截断正文预览时，中文标题取已校对中文正文的前 120 字；避免单独翻译半句话时补写内容。
- 日报已存在时不重新生成。需要更新日报时，模型接收缓存中文与原文证据，整合而非逐篇重新翻译。补充抓取的完整官方正文按自身内容缓存。

管理员可运行 `radar translate`，或 `POST /v1/admin/jobs?kind=translate` 补齐历史中文。队列同时覆盖主消息，以及已经保存正文、仍绑定消息的关联网页；主消息优先，共享内容只处理一次。补译只使用保存的原文，不重新抓网页或生成摘要；孤儿、空正文和旧内容缓存不进入队列。

`radar translate --force` 或 API 的 `force=true` 可跳过文档级等待间隔及旧尝试次数，但仍须满足持久调用记录的恢复条件。它不能重置语义修订预算、重发结果未知的调用、重新抽审同一被否决候选，或重做已通过段落。普通自动任务保留重试间隔与次数上限。API `/v1/status` 的 `translation.counts` 继续统计主消息，新增 `resource_counts` 单独统计有正文的关联网页；状态查询不创建翻译，也不调用模型。管理任务消息分别显示两者的已完成和待审数量，不能以主消息全部有中文推断网页全文已经补齐。

排查失败时先依据固定错误码和保存的调用记录定位故障，修复通用逻辑。只有满足恢复条件时才使用 `radar translate --limit 1 --force` 等正式入口。`--limit` 仅限制本次进程的数量，不修改服务器配置、原文或缓存键；仍使用正常队列、草稿恢复与质量门槛。已有任务运行时拒绝启动，避免干扰在线任务。任务完成表示这次处理结束，应同时查看译文状态，不能据此认定全部通过。

修复调用或输出格式故障后，可运行 `radar translate --limit 100 --errors-only --force`，只恢复当前有关联的已有 `error` 缓存。该范围不会创建新缓存或绑定，也不会重试 `review_required`、`ready` 或余额不足项；领取任务时再次核对错误状态及租约，防止排队后状态变化导致误重试。`--errors-only` 必须与普通 `translate --limit` 合用，不能混用复核、文件或日期选项。每份错误恢复后仍须通过原有质量门槛，不能把格式恢复视为内容批准。

服务日志中的 `translation_failure` 仅记录缓存 ID、初稿 / 修订 / 独立审计阶段、异常类、HTTP 状态及固定错误码。它区分连接、超时、模型输出格式、段落对应、原文保护项校验等故障，不记录原始异常、模型响应、原文、候选译文或密钥。先依据错误类型修复通用逻辑，再由正式服务器流程恢复，不能将所有失败都解释为网络故障。

发现历史错译后，开发者修复服务器逻辑，再使用正式重审入口；该入口仅接受已有记录范围，不能输入替换文字：

```bash
radar translate --recheck-article ARTICLE_ID
# 可重复 --recheck-article，内容相同的缓存只处理一次。
radar translate --recheck-editorial
```

历史编辑记录先恢复保留的机器候选；没有可靠机器候选的受影响段落才按原文重新生成。未被编辑的其他段落保留草稿。旧候选、历史标记及复核来源保留在审计历史中，不传给独立审核模型。通过后活动内容使用服务器生成结果与模型审计记录，不再保留人工批准标记。普通阅读不调用此入口。

重审尊重既有任务和数据库租约，未通过时不会发布候选。通过当前策略且原文/候选指纹一致的缓存直接复用；`--force` 也不能重新抽取同一候选的批准结果或清空历史预算。重审不会使其他已完成缓存失效，也不会调用全库翻译补齐。

## 跨任务调用记录

每个段落追加独立的 `workflow_history`，将原文、候选指纹、审计策略和调用阶段绑定。请求开始前先持久保存预留记录；有效响应、服务器生成的候选和审核结果在同一次受租约保护的写入中保存。进程在两者之间退出时，后续任务会保留未知状态，不将租约过期解释为可再次调用。旧版仅有 `running` 或笼统 `error`、没有明确结束记录的缓存同样不能自动解禁。

修订次数按已有历史和新预留累计，跨服务实例、任务重启及强制入口保持。正确初稿允许在首次校对时保持原样并接受第一次独立审核；已有否决时，服务器可在剩余预算内按审核意见修订，只有发生实质变化的新候选才接受新的审核。修订原样返回已被否决的文字，或形成候选循环时停止，保留全部疑点及历史，不发布整篇中文。

余额不足保存明确的失败结果，等待充值，不消耗语义修订轮次。明确结束的连接、超时、429 或 5xx 故障有独立的有限恢复预算；输出格式恢复和批量 ID 错位后的逐段恢复也不能因新任务或 `force` 无限重置。队列先检查这些条件，再应用文档数量上限，避免无法继续的旧记录挡住新内容。机器校验复检仍遵循下文的独立严格条件，不通过调用记录替换模型意见。

这些记录约束服务器执行行为，不能证明模型对每篇内容的判断都正确。未通过的候选继续保留原文供阅读，开发者通过通用实现和回归改进准确性。

## 机器检查修复后的缓存恢复

提交 `a510803` 修复了旧机器误报导致的重复修订：即使同一候选已有校对和独立审计通过，旧 `part.ok=false` 仍会进入模型修订；耗尽调用次数后则无法自动恢复。新流程先进行有数量上限的本地机器复检，再决定是否需要模型。它不消耗或重置模型尝试次数，不清除余额告警。

仅当当前内容缓存、完整原文分段、候选与草稿完全对应，两个模型记录均为当前策略、明确批准、指纹一致且无语义疑点，旧问题全部来自保存的机器检查，而且当前机器检查已全部通过时，服务器才复用该候选。过期策略、指纹变化、未知额外疑点、人工编辑标记、正在重审或未到期租约均不能走此路径。已通过的其他段落也必须满足当前校验，整篇才能发布。

原文、候选、模型批准结论及其审核历史保持不变；服务器另追加 `machine_history`，记录旧机器问题、当前结果、策略、指纹及时间。只修复部分段落时，其余语义否决继续保留，整篇仍不可见；本轮不因这次局部恢复而再次请求模型。重复复检无新变化时不写回。

正常后台翻译和汇总证据准备会自动执行这一步，不要求手机逐篇操作。正式运维入口为：

```bash
radar translate --revalidate-machine --limit 100
```

此命令仅检查当前有文章或网页绑定的已有待审缓存，不创建新翻译，不调用模型，也不要求模型密钥。它遵守任务空闲、租约及配置数量上限，不能与 `--force`、`--errors-only`、文章重审、文件或日期选项混用；不接受替换文案。结果中的 `machine_revalidated` 表示发生机器复检状态变化的缓存数，不等于新增整篇中文数。

## 余额不足提示

DeepSeek 返回 HTTP 402 时，服务端持久保存账户告警，手机首页、文章详情和设置显示“DeepSeek 余额不足”。已有译文与原文继续可读。识别依据为官方 [错误码说明](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)，401 授权错误、429 限流和服务器错误不会误报为余额不足。

同一批剩余翻译停止发起新调用，已经在途的调用可能完成；保存的翻译草稿不会丢失，余额错误也不占用内容的最大重试次数。充值后，下次定时或管理员触发的翻译调用成功会清除告警，未完成翻译从已有进度恢复。服务重启不会清除未解决的告警，较早开始的成功请求也不能覆盖后来发生的余额错误。

App 在前台每 30 秒更新服务状态，重新进入前台也会刷新；离线时明确标注缓存告警为“上次记录”。这是 App 内持续提示，尚未接入系统推送。阅读和状态刷新不调用翻译模型，也不主动轮询账户余额。

## 质量门槛

先生成译文，再由模型调用逐句对照原文修订，随后由独立调用只对照原文与候选进行审核，不接收修订阶段的批准结论，也不输出替换文字。重点检查否定、推测、引用归属、开放权重与开源、研究结果与证明、收入与利润、规模与质量，以及遗漏、增译和普通英文漏译。原始内容和辅助译文均视为不可信数据，不执行其中的命令。

机器检查、修订模型与独立审核必须同时通过。未通过的段落将带着具体问题进入下一轮服务器自动修订和复审，默认最多两轮；已通过的段落不会反复处理。余额不足或中断时保留草稿与阶段进度；独立审计阶段失败后无需重新翻译原文。审计策略、模型、时间和原文/候选指纹持久保存，结果不能套用于后来被修改的文字。

多段审计若返回的 ID 有缺失、重复或错位，整批批准结论作废，服务器改为逐段请求，仍要求每个 ID 精确对应。每段完成后立即保存原有质量检查与审计结果；中途失败时，已通过段落保留，剩余段落沿用逐段方式。单段 ID 错误仍拒绝，语义否决仍进入有界修订，不通过重映射 ID 或补写批准结论来恢复。

初稿、修订和独立审计共用结构化响应恢复：若输出不是合法 JSON 或违反本地结构约束，服务器最多补充一次格式说明并重新请求，原文、保护占位符与输入候选保持相同。结构错误的说明只含当前阶段的本地 JSON Schema 和白名单错误类型/字段位置，不包含模型先前的响应、批准结论或任意错误文本。缺少 `approved` 等必填字段时由模型重新完整输出，服务器不补默认批准。原文保护占位符缺失或重复时，共用这一次恢复机会：仅反馈输入序号、生成标记和原文/输出次数，由模型根据相同输入重新完整生成。程序不会自动补链接、修改译文或返回上次失败正文；JSON 与占位符错误交替出现时也不会增加调用上限。第二次仍不合格则保留错误；有效的语义否决不会触发格式重试，ID 错误继续直接拒绝，恢复后的候选仍须通过完整质量门槛。当前使用 DeepSeek 的 [Chat JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)，最终结构与质量仍由本地严格校验，不声称模型接口强制执行全部 Schema。

校对和审计的疑点列表完整保存，不因超过固定条数而丢弃审核意见。任意未解决疑点仍会阻止通过并进入有界修订；即使模型同时返回 `approved=true`，非空疑点也不能发布。模型响应总长度、输出段落数、并发与修订轮次仍受限制；文章级状态展示前 30 条问题仅为摘要，不影响段落内完整的纠错依据和审计历史。

审计提示要求每条疑点定位原文与当前译文的具体差异，避免将已通过的检查、等义措辞或核实后无误的猜测写入问题列表。校对阶段必须按原文核实这些意见，不能照单接受而引入新内容。服务器不会按关键词删除审核意见，也不会由开发者裁定某篇候选通过；模型返回的非空疑点仍完整保留并阻止发布。

程序检查数字/版本、百分比、货币符号、链接、@账号、中文覆盖、明显删漏以及输出段落是否完整对应。数值对应校验集中在 `translation_numbers.py`，比较数字及其出现次数。合法的英文千分位可与无分隔写法对应；中文逗号、顿号仍分隔列表数字，不将 `0.864，129` 合成一个数值。已知数量单位可等价转换，例如 `13 million` 与 `1300 万`、`7B` 与 `70亿`；单位可以紧邻中文，如 `7B偏好模型`，但不把 `7Beta`、`7B2` 等标识当作十亿单位。小数和版本号保留数字形式，明确的一元负号不能丢失；范围连接符和 `GPT-5` 等标识中的连字符不作为负号。

月份支持全称、缩写及中文形式。`Jan`、`Mar` 与 `May`、`March` 等歧义词结合日期上下文判断；独立的 `Jan, Feb, Mar` 月份列表可对应 `1月、2月、3月`，普通人名或动词用法不只因首字母大写就转成月份。既有的人名提示与日期边界检查保留，也不从小数或版本号末尾截取日期。规则仅覆盖明确的对应形式，无法据此判断所有日期或人名语义。

数字后的 `percent`、`per cent`，以及阿拉伯数字前的“百分之”，可与 `%`、全角 `％` 对应；数字和百分比标记分别核对，不能省略单位或借等价写法更改数值。`percentile`（百分位）和 `percentage points`（百分点）不会按百分比归一化。正文 @账号按 ASCII 字母、数字及下划线识别边界，允许紧邻中文，并核对名称和出现次数；相邻的 ASCII 邮箱字符和域名形式会被排除，避免把常见邮箱当作社交账号。URL 内的账号由完整链接校验负责，不再重复计入正文账号检查。

EUR、GBP 与明确货币语境中的 euro/pound 词支持中文货币等价表示，重量 pounds 不按英镑处理，歧义仍交给独立语义审计；引用帖的账号/时间、链接和 `$5m` 一类紧凑金额用可还原占位符保护，普通英文金额描述仍须翻译。无法通过检查或模型仍有疑点的内容标记 `review_required`，不对外发布候选译文。模型校对不能保证零错误，产品保留原文与一手链接，便于核验。

历史验收曾通过直接编辑修正品牌、风险等级和主客体表达，缓存保留了先前译文与编辑原因。用户已明确这不是开发者应采用的处理方式：这些样本应作为服务器回归与自动重审的输入，后续内容质量由统一的服务器逻辑决定。

2026-09-08 已由上述正式 CLI 完成 4 份历史记录的自动重审；活动结果全部具备当前机器审计，旧编辑仅留存历史。首轮未通过的网页经服务器续审修正，已通过段落复用；重复运行没有再次处理缓存。详细运行证据见 [验证记录](VALIDATION.md)。

## 技术语境与公式（0.10.0）

翻译、校对和独立审计都接收原始标题与有界正文上下文（最多 12,000 字符，长文选开头与结尾并注明省略），以及只包含文字的跨段候选。审计不接收先前的批准、问题解释或思考记录。服务器要求按研究对象、数学量和算法条件选择词义；难以确定的专名保留英文，解读可用原文支持的说明帮助理解，译文不能补造定义。

技术文档采用 `zh-context-audit-v2`。已完成的官方论文摘要或含 TeX 的文档会由正常队列安排一次复核：保留原候选及审计历史，先审核，必要时在既有上限内修正，再独立审核。非技术缓存不批量重翻，未完成或失败的旧流程仍使用原策略与原预算，未知调用不重放。队列每轮有界运行并继续轮转，不能以升级策略为由无变化重复抽审。

技术文档的 Codex 解读等待新版翻译审核完成，并将审过的中文纳入解读缓存标识。中文变化后重新生成对应标题/解读，已过期的技术解读不再展示；任务读取本身不会调用模型。本文策略提升概念核对能力，不保证模型绝无漏审。

TeX 公式在翻译请求中用可还原标记保护，机器检查逐个比较公式与定界符；分段不切断公式。HTML 采集优先保存出版方提供的 MathML `alttext` / TeX annotation 和 MathJax TeX，避免转正文或 Markdown 时丢失上下标；不会从已扁平化的 PDF 文本猜造公式。

App 使用锁定版本的 [KaTeX 0.18.7](https://github.com/KaTeX/KaTeX/releases/tag/v0.18.7)，代码、字体和 MIT 许可证一起打包，详情无需联网加载排版资源。支持行内、块级与常见多行 TeX；长公式可横向滚动，未知语法、渲染失败或超过排版上限时显示完整原始公式。列表用简短公式提示，点击详情查看完整排版。

## 可选免费辅助

默认使用 DeepSeek 加本地免费规则校验，不额外占用服务器运行另一个翻译模型。若已部署官方 [LibreTranslate](https://github.com/LibreTranslate/LibreTranslate)，可配置 `auxiliary_url`；如需鉴权，设置 `LIBRETRANSLATE_API_KEY`。该服务基于 [Argos Translate](https://github.com/argosopentech/argos-translate)，有额外内存、模型下载与许可证要求（LibreTranslate 为 AGPL-3.0），本项目未捆绑其运行时或模型。

辅助输出只作为 DeepSeek 的候选参考，不能跳过模型校对直接发布；辅助不可用时继续由 DeepSeek 完成。没有配置时不会把内容发送到未知公共翻译服务。

## 网页全文补读

0.3.0 起，网页原文和直接关联资料的全文也进入同一翻译 / 校对缓存，见 [READING.md](READING.md)。Markdown 链接先用可还原占位符保护；中文标点不参与 URL 比对。分段优先在段落或句末切开，避免破坏语义。Transformer 架构语境中的明确术语误译会被拦截。发现问题时完善统一检查和自动纠错流程，不直接编辑样本文字；自动校对仍可能漏错。

## 可选调用诊断

正式翻译命令可加 `--translation-diagnostics`，例如 `radar translate --limit 1 --force --translation-diagnostics`。该开关仅适用于 `translate`，默认关闭。启用时，`radar.translation` 的 INFO 日志通过独立 handler 写入 stderr；stdout 仍只输出原有任务 JSON。不会提升 root、HTTPX 或 OpenAI SDK 的日志级别，命令结束或失败后恢复原有日志状态，重复调用不会累积 handler。

`translation_completion` 行只包含阶段、安全模型标识、耗时、固定结束原因，以及供应商报告的输入、输出和推理 token 数；缺失的 token 数为 `null`，不能据此推断是否实际进行了推理。已知 DeepSeek 模型别名直接记录，其他模型使用短哈希标识。日志不包含原文、候选、思考内容、URL 或密钥；这项诊断不会改变队列范围、翻译内容、审核门槛或重试次数。
