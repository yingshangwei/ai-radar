# 摘要生成与事实审核

服务器负责日报和网页解读的生成、审核、修订和发布。开发者修复通用逻辑并验证，不直接修改文章、候选摘要或审批结果。全文翻译沿用独立的 [DeepSeek 翻译流程](TRANSLATION.md)，摘要审核不替代翻译审核。

## 发布流程

1. 从数据库读取本轮选中的原始消息与已保存的直接来源，冻结证据。审核材料保留正文、真实发布时间、来源链接和部分正文标记，不继续访问关联页面中的链接。衍生中文摘要与旧审批不能充当原始证据。
2. 生成候选日报或网页解读，按来源 ID、结构和字段限制校验。候选及调用进度保存在私有 `summary_reviews` 表，尚未通过的文案不进入公开接口。
3. 对日报头部和每条报道分别进行独立事实审核；网页解读按文档分别审核。审核应核对数字、主体、归属、时间、范围和原文支持程度，不把推测写成事实。
4. 仅对存在问题的部分自动修订，再针对新候选独立审核。批准必须对应当前证据、候选和审核策略，且没有未解决疑点。无变化修订、循环修订及超过预算都会停止，不能靠重复抽审获得通过。
5. 所有部分通过后，服务器在短暂的 SQLite 写事务中重新核对原始证据和已有发布版本。生成期间来源已变更或别的任务已发布时，不覆盖这些新进度。

进度跨任务和重启保存。已批准且绑定仍一致的部分复用；调用前先记录预算和预约，结果不明的未完成调用不自动重投。明确结束的限流、服务端错误或网络故障才允许有限恢复。手机查看和刷新只读取缓存，不触发模型。

网页审核未通过时，手机显示“网页解读尚未通过自动审核，处理进度已保存，无需重新授权。”原文与可独立使用的已审核译文仍按原有接口规则提供。此前已经发布的日报和解读保留；它们不会因功能上线被自动改写，也不能据此声称已通过新增事实审核。

## 配置

```toml
[summary_review]
enabled = true
max_calls = 64
max_correction_rounds = 2
max_format_retries = 1
max_prompt_chars = 400000
```

`max_calls` 是同一证据与配置下整个候选流程的模型调用预算，包含生成、审核、修订及恢复，不随普通重启或 `force` 清零。每个问题单元最多修订两轮；结构错误最多反馈重试一次。已知临时故障最多额外恢复两次，间隔 60 秒和 300 秒，并同时受总预算限制。超长审核材料直接保留为待处理错误，不截断材料后批准。

默认审核器使用 `[provider]`，可独立配置完整的 `[summary_review.provider]`，支持同一 Provider 体系的 Codex、Claude、自定义 CLI 或模型 API。例如：

```toml
[summary_review.provider]
kind = "openai_chat"
model = "your-review-model"
base_url = "https://your-model-provider.example/v1"
api_key_env = "SUMMARY_REVIEW_API_KEY"
timeout_seconds = 240
```

密钥仍仅放服务端环境文件。审核器配置为完整对象，不与生成器字段逐项合并；切换证据、策略或配置会建立新的处理身份，因此不要把反复修改配置当作恢复失败审核的方法。显式关闭审核会关闭这道门槛；明确选择 `extractive` 时仍是带标识的离线摘录，不声称经过模型事实审核。

调用次数是 Provider 调用次数，不等于账单请求数。API SDK 可能在一次调用内进行有限重试，记录中给出保守请求上界；CLI 内部请求数未知，上界记录为 `null`。现有 DeepSeek 翻译余额告警保持原流程；不能把它解释为已覆盖所有可替换摘要 Provider 的账户错误。

## 验证与限制

本地回归覆盖故意错误的合成数字、修订后的重新审核、预算与租约、未知结果、重启复用、候选隐私、来源变更及并发发布。发布事务当前要求 SQLite；其他数据库类型会拒绝发布，尚未实现等价并发保护。

模型审核可以减少事实错误，不能保证绝对准确。原始来源和审计历史始终保留。自动化测试、真实模型调用、实际生产内容通过审核是不同证据，部署与真实验收状态见 [验证记录](VALIDATION.md)。
