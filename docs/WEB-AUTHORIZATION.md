# 网页采集与一次授权

App 0.5.0 将入口改为「你的雷达 → 网页采集中心」。正常流程只有首次网站授权，之后自动读取、保存、翻译及总结，无需逐篇点采集或确认正文。

## 使用方式

公开网页由服务器定时采集，包括需要浏览器渲染的公开页面；已取得正文的网站显示「正文已采集」，无需授权。来源状态区分自动处理中、临时失败、限流、登录/访问验证和明确访问限制，不能因数据库里没有网站授权记录就要求登录。

服务器网络遇到网站验证时，选择该站的「开启手机自动读取」，首次允许手机读取该站文章，并在页面上完成网站自己的登录或人机验证。文章加载后自动保存并返回 App；同站待处理文章会在 App 前台依次读取，不再要求预览、复制或提交。使用阅读令牌连接的设备首次还需保存管理令牌；若之前已保存，升级后继续使用。

手机模式访问网站使用**手机当前网络**，与原来的腾讯云远程画面不同。网站登录状态保存在 App 自己的 WebView 中，可供后续同站访问使用；不会上传 Cookie、密码或表单字段。许可按服务地址和网站域名保存，只覆盖该域名及其 www 别名，可以暂停或恢复。

手机补采在 App 前台运行，每五分钟及回到前台时检查，每轮最多三篇。关闭 App、切到后台、进入采集中心或撤销许可时停止新读取和提交。临时失败文章冷却三十分钟，队列会跳过这些文章继续处理后续内容；真正遇到登录/验证码时暂停该网站并提示重新验证。网站可以主动使登录失效，因此一次许可会一直保存，但无法保证第三方网站永远不再要求验证。

App 不会操作或绕过验证码。可见网页完成验证但没有发生跳转时，会继续检查当前页面正文并自动接续；这不会重复刷新网站。源站只支持 HTTP、发生未确认的跨文章跳转或仍然拒绝移动 WebView 时，保留失败状态，不把错误页面当作正文。

「高级备用方式」保留系统浏览器和手动粘贴，仅用于自动读取确实不可用的特殊页面。系统浏览器不会把其 Cookie 或正文自动交给 App。服务器浏览器作为另一种选项继续保留，使用腾讯云网络；此前反复验证可能与自动浏览器兼容性或网络信号有关，不能靠更换手机 Wi-Fi 改变服务器出口。[Cloudflare 官方支持说明](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)。

## 正文处理与缓存

- 服务器优先使用官方 API、RSS 和公开 HTTP 读取，必要时自动使用独立浏览器。明确的 robots 禁止、私网地址、文件体积限制和限流不会触发浏览器绕行。robots 结果在同一轮按源站缓存，压缩响应在压缩前后都限制大小。
- 手机使用离线随包分发的官方 Mozilla Readability 0.6.0 提取当前文章，先检查可见登录/验证控件，再排除输入框、表单、隐藏内容和编辑区；不加载额外远程解析脚本。只提交当前绑定文章的正文与直接链接，域名及文章地址由原生端和服务器分别校验。
- 管理令牌只发给自己的 API，不注入第三方网页。`GET /v1/browser/mobile-queue` 仅返回当前设备许可域名中的待处理文章；`POST /v1/browser/mobile-import` 限制 1.5 MB 请求、60,000 字符正文及 30 个直接链接。二者均要求管理权限。
- 手机正文保存到既有 WebDocument，来源单独记录于 DocumentCapture。不会将手机登录错误标成服务器登录成功。较晚完成的旧服务器请求不能覆盖手机刚提交的新正文。
- 保存后自动排队既有 read 任务，共用 DeepSeek 翻译/校对、可替换模型的中文解读及内容哈希缓存。同样内容重复提交不会重复翻译；正文改变才使旧解读失效。读取范围仍为原页面和直接关联资源，不继续向更深层扩展。
- DeepSeek 余额告警、尚未通过校对的译文状态，以及已有中文与原文切换保持原有规则。

## 服务部署

主 API 继续使用 127.0.0.1:18473。浏览器使用独立的 `ai-radar-browser` 用户、systemd 服务、127.0.0.1:18475；资料位于 `/var/lib/ai-radar-browser`（0700）。只在交互窗口存续期间监听本机 VNC 15989，不开放公网 VNC/CDP 端口。现有 Caddy HTTPS 代理承载经认证的 WebSocket，无需添加公网端口或更改其他网站。

先在新 release 中执行 `scripts/install-browser.sh` 准备依赖、私有 worker 密钥和 noVNC 资源，再部署 API 与浏览器 unit。`/etc/ai-radar/browser.env`（0600）由 systemd 注入两个进程；其中 `RADAR_BROWSER_PUBLIC_ORIGIN` 必须与 App 所连接的 HTTPS origin 完全一致。主服务的原 `/etc/ai-radar/server.env`、模型和社交密钥不变。

浏览器 unit 使用独立的私有临时目录、只读系统、禁止访问主服务数据和环境文件，限制 1.1 GB 内存、90% 单核 CPU、256 个任务。Chromium 自带沙箱保持开启；Ubuntu 的 userns 许可只适用于专用 Chromium 安装路径，不全局关闭 AppArmor。浏览器网络通过校验并固定公网 DNS 地址的代理，拒绝私网、元数据地址和非 80/443 端口。无下载、个人浏览器资料导入、密码自动填充或验证码自动绕过。

## 授权通道与依赖

服务器浏览器的创建/关闭会话、启停补采需要管理令牌。首次打开使用 90 秒内有效的单次票据，票据只放 URL fragment，随后兑换成仅限该窗口路径的 HttpOnly / Secure / SameSite=Strict Cookie。票据使用后立即失效，WebSocket 验证 Cookie、固定 Origin、会话期限且只允许一个观察端。页面不加载外部脚本，键盘内容只经过加密的 VNC 通道；不写入日志、正文、翻译或持久化页面存储。

使用 Ubuntu 官方包中的 Openbox 管理远程按键焦点，关闭桌面菜单和启动快捷键。使用官方 [Playwright](https://playwright.dev/python/docs/auth) 1.62.0 和 [noVNC](https://github.com/novnc/noVNC) 1.7.0，移动容器使用 Expo 55 对应的 [React Native WebView](https://github.com/react-native-webview/react-native-webview) 13.16.0。Python 依赖使用含哈希的 requirements.lock，noVNC npm 发行包验证固定 SHA-512 integrity 并保留许可证，浏览器二进制由 Playwright 官方安装命令下载。更新这些依赖后应重新验证沙箱、远程交互和网站兼容性。

### 一直连接、画面灰色

2026-09-07 已修复 noVNC 1.7.0 在部分 Android Chromium 上的初始化阻塞：可选 H.264 能力检测可能一直不返回，原版顶层 `await` 会阻塞整个模块加载。`scripts/patch-novnc.py` 校验原文件 SHA-256 后，应用已合并的[上游修复 7834e66](https://github.com/novnc/noVNC/commit/7834e66)，并处理检测 API 缺失或拒绝的情况。检测失败只关闭可选编解码器，不阻止远程画面连接。补丁记录和原许可证保留在资源目录中。

安装脚本生成独立的 `android-compat-v1` 资源目录，所有子模块也使用新路径，避免旧 WebView 缓存继续加载有问题的代码。页面先启动状态与关闭按钮、兑换单次票据，再动态加载画面组件；普通请求 15 秒、组件加载 45 秒、画面连接 25 秒超时后显示具体错误，验证正文请求单独允许 60 秒。实际连接前禁用「验证并补采」。

这项灰屏修复只更新服务器资源，已有 App 0.4.0 无需重装；手机自动读取功能需要升级至 0.5.0。若窗口仍显示旧的「正在连接」，点击 App 右上角「关闭」，回到授权中心重新打开；新窗口会依次显示验证窗口、加载组件、连接画面及已连接状态。网站自身的登录、验证码或访问限制仍需在画面中处理。

以上服务面向当前单用户部署；多用户网站账号隔离不在本次范围内。
